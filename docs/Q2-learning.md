# Q2：第一个 Vulkan 三角形

运行 `scripts/run.bat` 后，中央深蓝背景上会出现一个上红、左蓝、右绿的渐变三角形。它是渲染实验对象，尚未接入工程对象树，暂时不能选择、移动或保存。

## 一帧如何形成

1. C++ 定义三个顶点：每个包含二维位置和 RGB 颜色。
2. `Triangle::initialize()` 申请顶点缓冲和显卡可访问的内存，上传这三个顶点。
3. 顶点着色器读取位置，产生裁剪空间坐标，并将颜色传给后续阶段。
4. GPU 将三角形覆盖的区域转换为片元，并插值颜色。
5. 片元着色器输出每个片元的颜色。
6. `vkCmdDraw(..., 3, ...)` 指示 GPU 绘制三个顶点；Qt 随后提交并呈现画面。

这里的 RGB 渐变不需要 C++ 为每个像素计算。只需给三个顶点颜色，GPU 会计算中间颜色。

## 本轮四个术语

| 术语 | 在本项目里的作用 |
|---|---|
| 顶点缓冲 | 存放位置和颜色的 GPU 可读数据 |
| 着色器 | 在 GPU 上执行的小程序，这里使用 GLSL 编写 |
| SPIR-V | GLSL 编译后的字节码，通过 Qt 资源打包进 exe |
| 图形管线 | 把顶点格式、着色器、填充方式、颜色输出等规则组合起来 |

## 资源生命周期

- 设备初始化：创建并上传顶点缓冲。
- 交换链初始化：创建匹配当前渲染通道的管线。
- 每帧：清屏、绑定管线和缓冲、设置视口、绘制。
- 窗口缩放：释放和重建管线；顶点数据不必重新上传。
- 最小化导致 Qt 释放设备资源时：释放顶点缓冲，恢复后重新创建。
- 退出：先销毁缓冲，再释放它绑定的内存；Qt 实例最后销毁。

之前修复的按图像索引呈现信号量继续生效。本轮没有取消同步检查。

## 坐标与比例

暂不使用相机。顶点位置直接进入裁剪空间，中心为 `(0, 0)`；当前正高度 Vulkan 视口中，负 Y 在上方。显示区域使用居中的正方形视口，保证窗口拉宽时三角形不被横向拉伸。这与未来工程模型的 Y 向上坐标约定是两回事，Q3 会加入转换矩阵。

## 阅读顺序与练习

先看 `shaders/triangle.vert` 和 `shaders/triangle.frag`，再看 `src/render/Triangle.cpp` 顶部的顶点数组，最后阅读 `draw()`。

可以把顶部顶点的 `{1.0f, 0.0f, 0.0f}` 改成黄色 `{1.0f, 1.0f, 0.0f}`，重新运行，观察整个颜色渐变如何改变。GPU 自动测试固定检查原始红绿蓝配色，因此完成练习后应还原，再运行测试。

## 验收

- `scripts/test.bat`：编译着色器、程序和基础测试。
- `scripts/test-gpu.ps1 -Rounds 3`：分别在集显和独显测试连续帧、缩放、最小化恢复及退出。
- 图像检查覆盖顶部红色、左侧蓝色、右侧绿色、中心混合颜色和外部背景；纯色清屏不能通过。
- 每轮写入 `build/q2-intel-1.txt` 等报告，视口截图为 `build/q2-viewport.png`。

当前使用小型 host-visible/coherent 顶点缓冲，方便学习；大模型会改用上传缓冲与设备本地内存。当前仅绘制单个平面三角形，不启用深度测试，也不做光照和交互。
