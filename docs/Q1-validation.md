# Q1 验证记录（2026-09-05）

- Qt 6.10.3 / MSVC 2022 / Vulkan SDK 1.4.357.0。
- 构建与 Qt 无显卡烟雾测试通过。
- RTX 4060 Laptop：8 帧、3 次交换链创建；清屏像素读回、缩放与最小化恢复通过；包括销毁阶段的验证层错误为 0。
- Intel UHD：同样完成 8 帧、3 次交换链创建，清屏图像读回通过；验证层记录 1 次信号量复用错误，因此整体未通过。

## 原问题（现已修复）

错误：`VUID-vkQueueSubmit-pSignalSemaphores-00067`。呈现仍可能使用某个信号量，下一帧却再次对它发出信号。

检查 Qt 6.10.3 官方 `qvulkanwindow.cpp`：第 1279–1280 行按 frame 分配信号量；第 2060 行提交绘制、第 2108 行提交呈现都引用 `frame.drawSem`。这与本次验证层指出的按帧而非按交换链图像复用问题吻合。Nothing3D 的清屏类不分配这些信号量，也不能通过 QVulkanWindow 公共接口替换它们。

参考：[Qt 6.10.3 源码](https://github.com/qt/qtbase/blob/v6.10.3/src/gui/vulkan/qvulkanwindow.cpp)、[Khronos 呈现信号量复用说明](https://docs.vulkan.org/guide/latest/swapchain_semaphore_reuse.html)。

## 修复与复验

`QtPresentSync` 在初始化交换链时创建按图像索引的信号量，在 `startNextFrame()` 中选取当前已获取图像的信号量；窗口缩放或关闭时还原 Qt 原始句柄，再释放自建句柄。图形与呈现队列不同时，也为队列间交接创建按图像索引的信号量。

补丁使用 Qt 6.10.3 私有状态，放在独立适配器中，没有修改 Qt 安装目录或替换 DLL。CMake 精确版本、编译期和运行期检查共同防止误用其他 Qt 版本。未来应优先切换到上游修复或自行管理交换链。

复验：Intel UHD、RTX 4060 各三轮连续渲染，每轮超过 300 帧、3 次交换链创建；清屏读回、缩放、最小化恢复和退出通过，验证层错误为 0。脚本 `scripts/test-gpu.ps1` 记录每次实际 GPU、帧数、交换链次数和进程退出码；不会把独显回退当作集显测试通过。报告在 `build/q1-intel-1.txt` 等文件中。

验证层始终开启，没有用关闭检查或每帧强制 GPU 等待隐藏问题。正常运行仍按需重绘，只有 GPU 测试连续请求帧。

## 测试限制

首次隐藏启动的测试未出帧，之后改用实际可显示的窗口验证。界面截图由 QWidget 获取，其中嵌入的原生 Vulkan 子窗口可能不被包含；GPU 读回图像 `build/q1-viewport.png` 才是绘制内容验证依据。

当前测试没有运行 1,000 基本体性能场景，因为还没有几何绘制。Q1 不能代表最终编辑器性能。

双队列分支已处理但本机两款显卡使用同一个图形/呈现队列，尚无独立硬件验证。交换链销毁沿用 Qt 的 device-idle 生命周期；这次没有引入呈现 fence 扩展，不能据此宣称覆盖所有驱动的呈现销毁时序。
